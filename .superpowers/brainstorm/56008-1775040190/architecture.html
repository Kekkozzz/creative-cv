🎨 Material Transition System — Il cuore dell'effetto

Wireframe → Solido: come funziona tecnicamente

Ogni oggetto ha due mesh sovrapposti: wireframe + solido. Un uniform u_materiality (0→1) controlla il mix:

▢
0.0
Solo wireframe
Lines + EdgesGeometry
▢
0.25
Wire + glow
Emissive edges
◧
0.50
Semi-transparent
Fill + visible edges
■
0.75
Quasi solido
PBR + faint edges
■
1.0
Full PBR
Riflessi + ombre
// Custom ShaderMaterial (semplificato)
uniform float u_materiality; // 0.0 = wireframe, 1.0 = solido

void main() {
  vec4 wireColor = vec4(accentColor, 0.6);
  vec4 solidColor = pbrLighting(normal, viewDir);
  gl_FragColor = mix(wireColor, solidColor, u_materiality);
  gl_FragColor.rgb += edgeGlow * (1.0 - u_materiality); // edge glow fades
}

🗂️ Modelli 3D — Strategia di Produzione

Oggetti procedurali (Three.js)

Generati in codice, come il WizardScene esistente. Ideali per wireframe puro e forme geometriche.

  • Scrivania base (box geometry)
  • Monitor (box + plane per schermo)
  • Tastiera, tazza, libri semplici
  • Grid/particelle/linee decorative
  • Floating elements (git graph, lighthouse)

Modelli GLTF (Blender)

Per le versioni "solide" dettagliate. Low-poly ottimizzati, con PBR materials.

  • CRT monitor (retro_computer.glb già c'è!)
  • Monitor flat / ultrawide
  • Cuffie, pianta, badge
  • MacBook, standing desk (cap. avanzati)
  • Ologramma AI, server rack

💡 Approccio: parti procedurali per i primi capitoli (wireframe puro), poi introduci GLTF man mano che la materialità aumenta
